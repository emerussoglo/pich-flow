# FAQ et diagnostic

## Quelle URL dois-je appeler ?

En local, l'origine par défaut est `http://localhost:3000`. Les routes marchandes sont sous `/api/v1`, par exemple `/api/v1/payments/softpay`. Le dépôt ne fixe pas le nom de domaine public de l'API; faites confirmer l'URL et les éventuels rewrites avant de l'utiliser.

## Quel type de clé utiliser ?

Les routes `/api/v1/...` attendent `Authorization: Bearer <clé_API>`. Le centre développeur génère des clés `sk_test_` et `sk_live_`; le code associe chaque secret à son environnement. Les conditions d'activation des clés ne sont pas décrites ici.

## Pourquoi un appel de référence renvoie-t-il une erreur ?

Les endpoints `/api/reference/...` interrogent SasPay à la demande. Une erreur fournisseur est renvoyée en HTTP 500 par les handlers; vérifiez la configuration du service et ses logs côté serveur.

## Pourquoi ma commande reste-t-elle en attente ?

Une session créée ou un paiement initié ne signifie pas que le paiement est confirmé. Vérifiez l'état via `GET /api/v1/payments/:id/verify` ou, pour une référence déjà persistée, `GET /api/v1/payments/status/:reference`.

## Les webhooks marchands sont-ils livrés ?

Pas par le dispatcher présent dans ce dépôt : il journalise les événements mais ne fait pas de requête HTTP vers l'URL configurée. N'utilisez pas ce flux comme mécanisme de confirmation sans une implémentation et une vérification ultérieures.

## L'adresse de production `api.pichflow.com` est-elle valide ?

Elle n'est pas définie dans le code ou la configuration du dépôt et la résolution de ce nom n'a pas pu être vérifiée depuis l'environnement d'audit. Elle n'est donc pas utilisée dans les exemples.
