# Liens de paiement

Les liens de paiement sont gérés par des routes du tableau de bord protégées par la session utilisateur. Le code ne déclare pas de route `/api/v1/payment-links` authentifiée par clé API.

## Routes confirmées dans le serveur

| Méthode | Route | Accès |
|---|---|---|
| `GET` | `/api/payment-links` | Session du compte; accepte `applicationId` ou `appId` en query. |
| `POST` | `/api/payment-links` | Session du compte; `title` est requis. |
| `GET` | `/api/payment-links/slug/:slug` | Lecture publique d'un lien actif. |
| `GET` | `/api/payment-links/:id` | Session du compte. |
| `PUT` | `/api/payment-links/:id` | Session du compte. |
| `DELETE` | `/api/payment-links/:id` | Session du compte. |

Le middleware de session accepte un jeton Bearer de session; ces routes ne doivent pas être appelées avec une clé `sk_test_` ou `sk_live_`.

## Création (tableau de bord)

Le handler reconnaît `title` (requis), `description`, `amount`, `isFixedAmount`, `currency`, `country`, `usageLimit`, `requirePhone`, `expiresAt`, `redirectUrl` et `applicationId`. Il renvoie `success` et `paymentLink`, y compris `paymentUrl`. Le slug est construit par le serveur; l'application sélectionnée doit appartenir à l'utilisateur.

```json
{
  "title": "Commande de démonstration",
  "description": "Lien de test",
  "amount": 2500,
  "isFixedAmount": true,
  "currency": "XOF",
  "country": "BJ",
  "requirePhone": false,
  "expiresAt": "2027-10-19"
}
```

Un lien à montant libre doit omettre `amount`; le serveur le rejette s'il en reçoit un. Les montants fixes sont des entiers XOF d'au moins 200. `country` peut être omis; la configuration vérifiée de ce dépôt ne prend en charge que le Bénin (BJ) en XOF. `expiresAt` est une date `YYYY-MM-DD` et expire à la fin de cette journée UTC.

Le checkout public ne demande le numéro de contact que si `requirePhone` est vrai. Il utilise ensuite la redirection PayDunya hébergée pour que le client sélectionne un moyen activé sur le compte; aucun code opérateur n'est envoyé et PichFlow ne collecte pas les données de carte.

En production, configurez `APP_URL` avec l'origine HTTPS publique. En local, configurez `PAYDUNYA_CALLBACK_URL` avec l'URL HTTPS d'un tunnel vers `/api/webhooks/paydunya` pour recevoir les IPN; le callback vers localhost n'est pas joignable depuis PayDunya.
