# Portefeuilles et transferts

## API marchande

Les opérations ci-dessous nécessitent une clé API Bearer :

```bash
curl http://localhost:3000/api/v1/wallets/balances \
  -H "Authorization: Bearer $PICHFLOW_API_KEY"

curl http://localhost:3000/api/v1/wallets/rates \
  -H "Authorization: Bearer $PICHFLOW_API_KEY"
```

Elles transmettent les requêtes à SasPay et enveloppent le résultat sous `data` en cas de succès. Les soldes et taux exacts dépendent du fournisseur et ne sont pas inventés ici.

## Transfert inter-pays

`POST /api/v1/wallets/transfer` exige `from_country`, `to_country` et `from_amount`. Le serveur normalise le montant et génère une idempotency key si elle n'est pas fournie.

```bash
curl -X POST http://localhost:3000/api/v1/wallets/transfer \
  -H "Authorization: Bearer $PICHFLOW_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: a1b2c3d4-e5f6-7890-1234-56789abcdef0" \
  -d '{
    "from_country": "BJ",
    "to_country": "CI",
    "from_amount": "25000.00"
  }'
```

Le code ne fixe pas de devise source ou cible dans le corps de la route; n'ajoutez pas ces champs à titre de contrat sans confirmation du fournisseur.

## Routes du tableau de bord

`GET /api/wallets`, `POST /api/wallets` et `POST /api/wallets/transfer` existent également dans l'API du tableau de bord, protégée par session. Elles sont distinctes de `/api/v1/wallets/...`.
