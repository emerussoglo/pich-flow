# Intégrer PichFlow

Cette documentation décrit les routes réellement présentes dans le serveur Express de ce dépôt. Elle distingue les endpoints authentifiés par clé API, les routes de référence publiques et les routes du tableau de bord protégées par session.

<Warning>
  Le code monte l'API sous le préfixe `/api`. Les opérations marchandes sont sous `/api/v1`. Le domaine public de l'API n'est pas configuré explicitement dans le dépôt : l'adresse de production et son routage doivent être confirmés avant toute requête réelle. Les exemples utilisent `http://localhost:3000`.
</Warning>

## Points établis par le code

- Le serveur Express monte le routeur sous `/api`; les opérations marchand sont déclarées sous `/v1`.
- L'authentification de l'API marchand attend `Authorization: Bearer <clé_API>`.
- Les clés créées par le centre développeur comprennent une paire Sandbox (`sk_test_`) et Live (`sk_live_`).
- Les routes et les formats renvoyés par un fournisseur peuvent dépendre de l'environnement et du résultat SasPay.
- Les liens de paiement et les clients ont des routes de tableau de bord utilisant la session du compte; aucune route API marchand `/v1/payment-links` ou `/v1/customers` n'est déclarée.

## Limites connues

Le déploiement public de l'API, la disponibilité par pays, les tarifs appliqués et l'exécution effective des webhooks marchands ne peuvent pas être déduits du seul code. Les pages concernées signalent ces limites au lieu de présenter des comportements non confirmés comme garantis.
