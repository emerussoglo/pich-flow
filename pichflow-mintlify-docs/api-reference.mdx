# Référence API

La spécification [OpenAPI](./openapi.json) décrit les routes marchandes `/api/v1`, les routes de référence `/api/reference` et le récepteur de webhook SasPay. Elle est volontairement partielle : les réponses transitant par SasPay sont génériques et certaines routes du tableau de bord utilisent une session plutôt qu'une clé API.

## Base URL vérifiée dans le code

Le serveur local monte Express sur `/api` et les routes marchandes sur `/api/v1`. Pour développer localement, utilisez `http://localhost:3000` comme origine. Aucun nom de domaine de production ni rewrite API n'est déclaré dans `vercel.json`; les URL de production présentes dans d'anciennes pages ne sont donc pas reprises comme garanties.

## Authentification

Les routes `/api/v1/...` utilisent `Authorization: Bearer <clé_API>`. Les opérations de référence sont publiques. Le webhook SasPay entrant utilise les en-têtes de signature spécifiques et non la clé API marchande.

## Couverture OpenAPI

Sont notamment décrits : création de paiement, Softpay, checkout, vérification et retry, transactions, payouts, soldes/taux/transferts et références pays/réseaux. Les routes de compte, clients, liens, withdrawals et réglages du tableau de bord ne sont pas exposées sous le même mécanisme de clé API et restent hors de cette spécification.

Le playground est masqué : aucun serveur public fiable n'a été confirmé pour exécuter des appels depuis la documentation.
