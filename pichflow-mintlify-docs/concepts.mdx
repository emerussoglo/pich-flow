# Concepts essentiels

## Clé API et environnement

Une clé `sk_test_...` ou `sk_live_...` est liée à un environnement. Le middleware enregistre également l'application associée à la clé. Certaines opérations, comme l'initialisation d'un payout, contrôlent le scope (`payout` ou `both`).

## Paiement, session et transaction

- Un paiement Softpay est créé par `POST /api/v1/payments/softpay`.
- Une session hébergée est créée par `POST /api/v1/checkout-sessions`.
- Le point d'entrée unifié `POST /api/v1/payments/create` choisit Softpay lorsque `network` et `customerPhone` sont transmis; sinon il crée une session hébergée.
- La base interne distingue les sessions de checkout et les transactions. Une réponse fournisseur n'est pas nécessairement une transaction déjà finalisée.

## Référence et identifiants

La réponse du fournisseur peut fournir un identifiant de paiement. La route `/api/v1/payments/:id/verify` reçoit cet identifiant; `/api/v1/payments/status/:reference` consulte une référence interne présente dans la base PichFlow. Ne les intervertissez pas.

## Montants et champs

Le serveur normalise le montant avant de le transmettre au fournisseur. Les exemples utilisent des chaînes décimales telles que `"5000.00"` pour éviter les arrondis côté client; la validation exacte des décimales dépend du fournisseur.

## Liens de paiement et clients

Le code expose des routes de liens de paiement et de clients sous `/api/...`, mais elles utilisent l'authentification de session du tableau de bord. Elles ne sont pas des opérations de l'API marchande `/api/v1` par clé API.
