# Checkout hébergé

La route `POST /api/v1/checkout-sessions` exige `amount`, `customer_email` et `customer_name`. Elle transmet les autres propriétés reconnues au service SasPay.

```bash
curl -X POST http://localhost:3000/api/v1/checkout-sessions \
  -H "Authorization: Bearer $PICHFLOW_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": "12500.00",
    "currency": "XOF",
    "country": "BJ",
    "customer_name": "Awa Exemple",
    "customer_email": "awa@example.test",
    "customer_phone": "+22997000000",
    "description": "Commande de démonstration",
    "return_url": "https://shop.example.test/payment-return",
    "metadata": {
      "order_id": "order_demo_001"
    }
  }'
```

## Champs reconnus par la route

| Champ | Requis par le handler | Notes |
|---|---:|---|
| `amount` | Oui | Normalisé par le serveur avant l'appel fournisseur. |
| `customer_email` | Oui | Transmis au fournisseur. |
| `customer_name` | Oui | Transmis au fournisseur. |
| `currency` | Non | Défaut local : `XOF`. |
| `country`, `customer_phone`, `description`, `return_url`, `metadata` | Non | Transmis si fourni. |

Une réponse réussie renvoie `success`, `environment` et `data` avec la réponse du fournisseur. Le code ne fixe pas la forme des champs de `data`, ni le domaine de la page de paiement. Utilisez `data.checkout_url` seulement si cette propriété est présente.

Le retour navigateur (`return_url`) ne prouve pas à lui seul qu'un paiement est confirmé. Vérifiez le statut depuis votre serveur.
