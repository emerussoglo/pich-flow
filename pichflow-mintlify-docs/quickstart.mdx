# Démarrage rapide

Les commandes ci-dessous utilisent le serveur local du dépôt. L'application écoute sur le port `3000` par défaut; adaptez l'origine si votre configuration locale diffère.

## 1. Démarrer et vérifier le serveur

```bash
npm install
npm run dev
```

Dans un autre terminal, vérifiez l'état du serveur :

```bash
curl http://localhost:3000/api/health
```

La route de santé est déclarée par le serveur Express et retourne `status`, `service`, `env` et `timestamp` si l'application a démarré correctement.

## 2. Vérifier les pays disponibles

Les routes de référence ne demandent pas de clé API. Elles interrogent SasPay en direct et peuvent échouer si cette dépendance ou sa configuration n'est pas disponible.

```bash
curl http://localhost:3000/api/reference/countries
curl http://localhost:3000/api/reference/networks
```

## 3. Préparer un paiement Softpay

Créez une clé dans le centre développeur puis utilisez-la uniquement depuis un serveur. La base locale des routes marchandes est `http://localhost:3000/api/v1`; l'adresse de production n'est pas vérifiée par ce dépôt.

```bash
curl -X POST http://localhost:3000/api/v1/payments/softpay \
  -H "Authorization: Bearer $PICHFLOW_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 24d4aa13-5fe3-4fa3-9c8e-15e21ec178bc" \
  -d '{
    "amount": "5000.00",
    "currency": "XOF",
    "country": "BJ",
    "network": "mtn_bj",
    "customer": {
      "first_name": "Awa",
      "last_name": "Exemple",
      "email": "awa@example.test",
      "phone": "+22997000000"
    },
    "description": "Commande de démonstration"
  }'
```

La route exige `amount`, `network` et `customer`; les autres champs montrés sont pris en charge par le service appelé. L'en-tête d'idempotence est facultatif côté serveur, qui en génère un en l'absence de cet en-tête. L'exemple le fournit afin que l'appelant puisse réutiliser la même clé lors d'un retry de la même intention.

## 4. Confirmer le résultat

La réponse de paiement est transmise depuis le service fournisseur sous `data` avec un indicateur `success` et l'environnement. Consultez [Vérifier un paiement](./payment-verification) pour les deux routes de vérification.
